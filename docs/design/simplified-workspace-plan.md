# 简洁主界面与三类窗口修改方案

状态：2026-10-30已实施；自动及主要原生路径验证完成，全部DPI矩阵尚未穷举。
使用writing-plans整理实施步骤。沿用docs分类，不另建平行规范目录。

## 目标和范围

主界面服务选学生、看课表；管理操作有明确归属，避免多层课程弹窗。保持学生单学期、8/10节、个人统一单双节、日期转换、冲突检查、结构化JSON及不捆绑.NET的发布方式。不得增加学生重命名/删除、搜索、筛选、导入导出等新功能。

采用用户接受的方案：主窗口、课程与设置承载窗口、上课时段小窗口，共三类。相比全部内联方案，保留单时段弹窗可避免在窄窗口堆积复杂表单；相比仅隐藏入口，承载窗口合并列表与编辑，减少实际弹窗层数。

## 1. 窗口与入口

### 主窗口

默认600×600 DIP，顶部一行：学生选择｜第N周普通文本｜本周｜更多。仅三个可操作控件，无重复“课程表”标题，无左右切周按钮。

更多菜单按顺序提供管理课程、总体设置、分隔线、新增学生、刷新学生文件；无学生时禁用管理课程/设置，新增和刷新仍可用。保持鼠标、键盘、tooltip及无障碍名称。

课表滚轮切周，双击课程进入承载窗口的课程编辑页，双击空格进入带星期、节次、当前周预填的新课程页；保留双节配对预填。底部消息平时折叠，学期状态仅必要时出现。

新增学生表单在工具栏下方按需展开：姓名、创建、取消。默认蜡笔小新；创建成功后加载新学生、收起表单并重绘课表；失败保留输入、在主窗口底部报错。取消不写文件。展开期间暂时禁用学生切换、更多菜单及课表编辑入口，课表仍可浏览；Enter仅在表单激活时创建，Esc收起，关闭主窗口时有实际修改才提示放弃。收起后清除默认按钮并恢复焦点，避免Enter误建学生。

### 课程与设置承载窗口

建议默认600×600 DIP、最小520×480，标题“课程与设置（学生姓名）”，与主窗口居中，模态打开且不在任务栏另占入口。尺寸为本次设计选择，须用实际布局复核，不以固定像素遮蔽溢出。

顶部仅两个导航项：课程管理、总体设置；中间只显示一个页面；底部消息与确认区域由窗口统一拥有。按菜单入口直接选页，不让用户多走一步。

课程管理内部为列表页或课程编辑页，不并排挤入600 DIP。列表保留四列、按课程ID合并名称、组内排序、交替底色及圆角课程色；双击实际行编辑、真实空白新建，排除表头/滚动条。底部新建/删除，标题栏关闭。

编辑页显示返回课程列表、课程名称、颜色、备注及上课时段表。顶部信息Auto、中部表格占剩余空间、操作区固定；不沿用固定200 DIP表格高度。必须始终提供可到达的表内空白新增区域，不能因数据填满丢失入口。保留周次/时间/地点/操作列及双击新增/编辑，操作按钮不触发新建。

编辑页底部：编辑已有课程时左侧删除课程，右侧取消/保存；新课程不显示删除。保存成功返回课程列表并选中保存课程；取消和返回遵循离开草稿规则。主课表直接进入编辑后，保存也返回列表，窗口可继续管理，统一所有入口行为。

总体设置页复用现有规则和内容，只保留一份实现。学期/模式与课时参数/预览按任务分组；刷新直接生成，无成功或确认消息；恢复默认、改变日期等原有确认继续有效。底部恢复默认/取消修改/保存；保存留在设置页并重建干净草稿，取消修改恢复最近保存值并留在设置页。全部操作的命名应与实际行为相符。

### 时段窗口

继续320×340 DIP，新增/编辑共用，标签、注释、ASCII限制、周次筛选与时间编码不变。Owner为承载窗口，居中且仅一层子弹窗。确定只更新课程草稿；取消不泄漏修改。错误在本窗口底部，不转移到父窗口。

## 2. 状态与保存约定

- 承载窗口绑定打开时的学生；不在其中提供学生切换。主窗口被模态阻止，避免编辑对象漂移。
- 页面只有一份活跃草稿，不保留多个未保存页面。进入课程或设置编辑时，从WorkspaceViewModel当前已保存文档重新构造草稿，避免旧草稿覆盖刚保存的另一页。
- 课程/设置ViewModel提供基于真实字段的IsDirty判断，覆盖文本、单选、时间、时段添加/删除/编辑；初始化、打开下拉、刷新列表不算修改。无效输入仍能判断为修改，不调用Build来判断脏状态。
- 返回、切换导航、取消修改、关闭窗口若有修改，使用同一个窗口内确认：保存、放弃修改、继续编辑。“取消修改”的待完成动作是恢复最近保存值并留在设置页，同样不能无提示丢弃。确认前提交正在编辑的课时单元格。保存失败留在原页、保留输入，不执行待完成导航。
- 设置保存仍需保留学期起点变化的日期确认：先校验并构造候选，再在同一确认区域切换为“保存新日期/继续编辑”，不叠加弹窗或第二个确认面板。若由离开页面的“保存”进入此阶段，继续编辑、Esc及任何失败均清空原待完成动作并留在当前草稿；成功落盘才执行原导航。确认期间暂时禁止修改表单，避免确认对象与写入候选不一致。恢复默认等原有确认同样不能覆盖尚未完成的离开确认。
- 待完成动作只有一个（返回列表/切换到目标页/关闭）；确认期间不叠加导航或多个确认面板。继续编辑取消待完成动作。
- 保存：验证完整候选→StudentFileStore成功写入→更新WorkspaceViewModel→清除脏状态→执行待完成动作。失败不能先替换正式文档、关闭或显示成功。
- 删除整门课程必须确认并成功保存后返回列表；删除失败保留原页面。草稿中的修改不需要先保存再删除。删除新建但未保存的课程只通过取消处理。
- 每次页面保存后重新构造相关草稿。零课程可改模式仍按已保存课程数决定：删除全部课程并保存后，再进入设置即可修改；不能同一候选删除并改模式绕过。
- 主窗口在承载窗口关闭后始终重绘当前Workspace状态，不依赖ShowDialog()==true；页内保存后即使最后通过取消或标题栏关闭，也必须显示已经保存的结果。
- 文件外部修改继续拒绝覆盖，保留草稿和现有提示策略，不加入自动合并或静默重载。

## 3. 代码划分

保留Core领域/存储/JSON契约，WorkspaceViewModel继续是已保存学生状态的唯一来源。沿用简单MVVM，不引入DI容器、路由框架、消息总线或通用页面系统。

建议新增（下表Views、ViewModels、Resources均位于src/ClassSchedule下）：

| 文件 | 职责 |
|---|---|
| Views/StudentWorkspaceWindow.xaml及.cs | 唯一承载窗口、页面内容、父子窗口关系、底部提示/确认与焦点 |
| ViewModels/StudentWorkspaceViewModel.cs | 当前页面、课程/设置草稿及待完成导航，协调保存和离开草稿 |
| Views/CourseListView.xaml及.cs | 列表和实际行/空白命中，复用GroupedCourseTable |
| Views/CourseEditorView.xaml及.cs | 课程表单、时段表及打开时段小窗请求 |
| Views/SettingsView.xaml及.cs | 设置表单、单元格提交、滚轮与日历交互 |
| Views/NewStudentForm.xaml及.cs | 主窗口内临时姓名表单，复用NewStudentViewModel |
| Resources/Theme.xaml | 提取现有主题资源，集中维护，先保留已接受外观 |

修改MainWindow与CourseViewModel、SettingsViewModel，复用ScheduleWindow及其他现有控件。逐步将本次重做的布局写为XAML；主课表动态格子仍可由C#生成，不为追求纯XAML重写。ViewModel不得持有Window、控件或通过查找控件获取业务字段；命中、滚动、焦点保留在View。

主题迁入资源字典后，同步调整UiChecks的隔离资源加载：通过明确的ClassSchedule程序集资源URI加载同一份Theme，不能因App.xaml的MergedDictionaries改动而丢失样式，也不能重新触发生产App.OnStartup读取真实data。

DialogWindow只提取当前确实共用的提示、确认与位置能力；页面本身不伪装成Window、不调用DialogResult。避免叠加旧窗口Footer与承载窗口Footer。

旧CourseManagerWindow、CourseWindow、SettingsWindow、NewStudentWindow在所有调用及测试迁移后移除；CourseWindow.cs中的ScheduleWindow与颜色预览转换器先移入同名文件或所属视图，不能随旧课程窗口误删。

## 5. 完成判据

日常主界面仅三个可操作控件；管理与设置共用一个承载窗口；编辑课程不再额外弹窗；只有单时段继续使用子窗口。所有草稿退出路径一致，失败不丢内容；主窗口显示全部已保存变化；旧页面没有第二套实现。课程规则、文件结构、已接受的输入方式和运行时发布契约保持不变。

规划复核：独立只读审查补足了设置日期二次确认与待完成导航的协调，以及“取消修改”的草稿保护；两项已写入状态约定和验收任务。规划阶段文档链接检查通过；该阶段尚未改程序，后续实施结果见下文补充。

实施补充：IsDirty使用明确可编辑字段的序列化快照作比较，不以Build判断；课程Build先克隆再规范化，失败不改变输入。新增表单关闭确认期间禁用创建，确认区默认焦点为继续/取消。课程表使用填充高度加固定空白新增带，不再用行数撑高外层页面。主题及布局已提取，未将主课表动态格子强行改写为XAML。
