# 课程表第一版设计方案

状态：用户要求开始后，第一版已按此方案实现。验证范围见[验证记录](../verification/2026-10-29.md)。

## 1. 目标与依据

Windows 桌面程序，用于学生查看和编辑单学期课程表。严格支持每日 8/10 节、每人固定单节或双节，不扩展教师课表、任意节数、多学期、云同步、自动排课、导入导出或打印。

依据：[产品需求](../requirements/requirements.md)、[数据格式](../requirements/data-model.md)、[验收清单](../requirements/acceptance.md)、[UI参考](../ui/README.md)，以及本次对话中用户确认的修订。已确认规则集中维护在requirements中；本方案的待审阅建议不能覆盖这些规则。

采用[项目代码审查skill](../skills/project-code-review/SKILL.md)的职责边界、最小抽象、状态生命周期和可观察验证要求；该 skill 的完整审查、清理、提交推送流程不属于本次规划范围。

成功标准：新建学生后能设置时间、创建和修改多时段课程、切换学生与周次、关闭重开后数据一致；周日归属变更保持所有课程实际日期；任何失败均不丢失已保存数据，错误和警告只进入对应窗口底部提示栏。

## 2. 已选方案与取舍

- 采用 WPF + 简单 MVVM。与用户确认一致；不采用 WinUI 3，减少本项目的部署及窗口行为复杂度。
- 采用每学生一份 UTF-8 JSON，无数据库和共享 settings.json。便于备份和检查，代价是必须处理文件损坏、外部修改和安全替换。
- 采用普通模型、具体业务类和具体存储类，手动组装对象。不引入 MVVM 框架、DI 容器、消息总线、通用仓储或插件体系。
- 设置集中一页；主窗口、总体设置、课程管理、学生管理各自负责单一任务。课程时段继续用独立子窗口编辑。

## 3. 数据契约

路径固定为 `AppContext.BaseDirectory/data/姓名.json`，不使用进程工作目录。显示姓名唯一取自文件名，不保存重复的 studentName。每份文档顶层为 schemaVersion、settings、courses，schemaVersion=2，旧格式拒绝加载。

### settings

| 字段 | 类型与规则 |
|---|---|
| firstWeekMonday | ISO 日期 yyyy-MM-dd，必须星期一 |
| totalWeeks | 正整数；初版建议 UI 范围 1–104，自动扩展也受此范围约束，超出时提示且不提交 |
| sundayBelongsTo | previous / next |
| classesPerDay | 8 / 10 |
| classesUnit | one / two，默认one；已保存课程为0时可改，有课程时锁定 |
| timeGeneration | durationMinutes、oddBreakMinutes、evenBreakMinutes、morningStart、afternoonStart、eveningStart |
| classPeriods | 按 period 升序的数组，每项 period、start、end；必须完整覆盖 1..classesPerDay |

timeGeneration 的时长默认45，范围1–180分钟；两个课间为0–99分钟整数，默认10/20；三个起点默认08:00、14:00、19:00。时间使用HH:mm，不允许跨午夜。起点通过小时/分钟分选，上午小时8–11、下午13–16、晚上18/19，分钟00..55步长5；已有不支持的值保留并显示原值，完整选择才替换。

classPeriods是实际课时的唯一依据；timeGeneration仅供主动生成使用。开始、结束可编辑，时长=end-start、间隔=下一节start-本节end只读计算；第4、8节和当天最后一节间隔显示“—”。各节要求start < end，前一节end <= 后一节start。生成失败保留现有表格。

生成时分别从上午、下午、晚上起点开始，上午1–4节、下午5–8节、晚上9–10节，各段内部按节次奇偶加入间隔；不靠短课间推导下一段起点。8节仍保留 eveningStart 参数。手改时刻不会随参数输入自动覆盖。

### courses 和 schedules

课程字段为 id（GUID）、name（非空）、color（#RRGGBB，只读展示）、reminderCount（默认3）、reminderIntervalMinutes（默认3）、reminderDurationMinutes（默认1）、schedules（至少一项）。note已移除。同名课程允许存在，身份和颜色绑定按 ID，不按姓名或课程名推断。

时段字段为 id（GUID）、weeks（升序无重复整数数组，非空且位于1..totalWeeks）、dayOfWeek（周一1至周日7）、startPeriod、location（可为 ""）。two 模式仅允许1/3/5/7及10节时的9；one模式允许全部合法节次。不保存时段级单双节、结束节次或重复的实际日期。

不保存当前浏览周、自动计算的当前周、通知队列、窗口临时状态、时长和课间计算值。不添加时间戳、审计记录或单独学生 ID；目前没有跨文件引用。

读取严格校验 schemaVersion、字段类型、枚举、GUID 唯一性、日期、课时、周次和冲突；不把缺失或无效字段悄悄补成默认值后覆盖原文件。未知版本报错并保留源文件，未来确有升级时再实现明确迁移。

## 4. 日期与周次

令 M 为第一周周一，n 为周次。周一至周六日期=M+7(n-1)+(dayOfWeek-1)。周日 previous 日期=M+7(n-1)+6；next 日期=M+7(n-1)-1。

当前周：previous 时为 floor((today-M)/7)+1；next 时为 floor((today-M+1)/7)+1。必须数学向下取整，不用负数整数截断。使用本地 DateOnly，不进行 UTC 日期换算。

previous 按周一到周日排列，next 按周日到周六排列。顶部只显示“第 N 周”；各列显示星期和真实 MM/dd。保留回到本周和课表区滚轮切周，不显示前后箭头。

学期外默认展示最接近的第1/末周，同时显示持久状态“学期尚未开始/已结束”；它是页面状态而非会自动消失的警告。翻页限制在1..totalWeeks，边缘按钮禁用。“回到本周”同样采用该规则。滚轮采用累积刻度并限制连续切换频率；可滚动容器优先处理自身滚动，避免设置表滚动误切周。

### 周日归属切换

在设置草稿内执行，保存前不修改当前学生或磁盘：

1. 用旧设置展开每条时段的所有实际日期。
2. 按新归属和原锚点将日期重映射到周次。previous→next 周日+1；反向周日-1，其余不变。
3. 若产生第0周，将锚点向前移动一周，再映射全部课程日期；非周日课程的周次因此也+1，日期不变。
4. 按最大结果扩展 totalWeeks，不自动缩减；没有越界安排则不扩展。清空课程的学生切换归属无需扩大范围。
5. 对每条记录重新组织 weeks、排序，完成日期集合相等与冲突校验后整体保存。仅归属切换无需拆分同一星期、同一节次的记录。

保存成功后底部说明锚点或总周数的自动调整。反复切换保持所有课程日期，但不保证学期范围自动缩回原长度。该行为写入帮助说明。

为避免同次编辑出现“保持日期”与“改变学期日期”相互矛盾，建议归属转换与手动修改第一周周一/总周数分两次保存。用户同时修改时在底部说明应先保存归属转换，再调整学期，不提交部分更改。归属预览始终从打开设置时的原始快照计算，而非反复迁移已变更草稿；未保存时切回原选项恢复原始范围，不累计扩展。

手动修改第一周周一属于用户主动调整学期：保留课程周次，因此改变实际日期；保存前在设置页内列出变化摘要。缩短总周数或10→8使课程失效时阻止保存并列出受影响课程。8→10新增晚间时间，不覆盖原1–8节。模式变更单独以已保存课程数判断：0时可改，有课程时只读，恢复默认不更改模式。

## 5. 窗口与流程

### 主窗口

- 无右侧课程栏。学生选择框无三角，显示与下拉外框均88 DIP；右侧为周次文本、本周和矢量设置齿轮。
- 齿轮圆角菜单依次为总体设置、课程管理、学生管理、更新学生信息；末项执行学生文件扫描与重载，保留错误提示和当前周次。
- 课程块只显示名称和地点，双节跨两行，同课同色。长文本截断并提供 tooltip。
- 空格双击新建，预填星期、配对节次和当前浏览周；默认 weeks 为当前浏览周，用户再调整。已有块双击编辑整门课程。
- 学生切换重新计算本周，不保存上次浏览周。刷新保持现有浏览周，若参数改变则夹取合法周次。
- 当前文件删除：选择按姓名稳定排序的首个有效学生并提示；全空则显示新增入口。非法文件不列为可切换学生，提示文件名和原因，不阻塞其他合法学生。
- 管理课程用课程名/周次/时间/地点四列，按课程ID聚拢时段并纵向合并名称；实际行双击编辑、内容区空白双击新建，不依赖旧选择；表头和滚动条排除。下方新建/删除/确定，确定或Esc/标题栏关闭，无须切到课程实际出现的周。编码由核心CourseTimeCode生成/解码，规则见数据格式文档，JSON不重复存储。

### 新增学生

独立StudentManagementWindow，列表与姓名框共用，新增/更新/删除。新增默认单节、每日8节、20周，第一周周一取当前自然周；创建默认文档由WorkspaceViewModel.CreateStudent协调，不保留旧NewStudentForm/NewStudentViewModel。更新保留文档字节并同步改备份文件名，检查指纹/重名/备份冲突；删除固定底部是/否确认，默认否，同时删JSON与bak。StudentFileStore先获取两个文件的操作句柄，删除主文件失败恢复备份原名；不声称断电时跨文件原子事务。窗口不复制存储与校验逻辑。

### 设置窗口

单页：基本信息、课时参数、分段起点、实际课时表。基本信息顺序为第一周周一、总周数、周日归属、每日课时、课程模式。提供生成默认时间、恢复默认、取消、保存。

CanChangeMode由打开时原文档课程数决定：0时可改，有课程时只读；StudentFileStore在保存前再次检查磁盘旧文档课程数，不能同次删除并改模式绕过。先删除全部并保存后，可在重新打开的设置中再改。刷新图标先提交单元格再直接生成，不确认、不显示成功消息；异常通过底部提示，保留原表。“恢复默认课时”仍需确认，仅恢复timeGeneration和classPeriods，不清空课程或更改其它参数。

StudentWorkspaceWindow在设置页活动时处理PreviewMouseWheel，转给SettingsView统一滚动SettingsPage外层ScrollViewer，覆盖表格、下拉和底部按钮；日历浮层排除并自行按月消费。时间下拉浮层自行消费滚轮，保持展开及选值不变，不穿透外层页面；SettingsView处理页面滚轮前关闭所有时间浮层。无箭头模板不预留箭头空间，最多4项，每项28 DIP，滚动条统一11 DIP。日历只显示一个月，相邻月格内容隐藏且不可点击；翻月不改变所选日期。

### 课程与时段窗口

课程编辑只维护一门课程的独立草稿，字段名称、只读颜色、提醒次数与间隔，时段表列固定为上课周次/时间/上课地点/提前提醒，双击真实空白新增、实际行编辑，不保留额外空白行，表头右侧＋新增；数据区最多5行并内部滚动。已有行双击编辑，时段窗口内保存、取消或删除，无表内操作按钮；删除课程仅编辑模式显示。

时段编辑是课程编辑的 owned modal 子窗口，确定仅更新父窗口草稿；只有课程窗口保存成功才落盘。取消子窗口、取消课程窗口均不泄漏修改。

周次仅接受ASCII数字、英文连字符/逗号/空格，WeekSelectionParser解析去重升序、格式化压缩区间。单/双周按绝对周次筛选。时间使用CourseTimeCode.EncodeTime/DecodeTime，单节401、双节30102；按学生模式检查配对。SchedulePresentation统一排序与展示，GroupedCourseTable使用Grid.RowSpan真正合并名称，表头固定、正文统一滚动，按课程ID选择与删除。

课程颜色是名称输入框后的只读色块；CourseColors在已有色相的最大圆周空档中部随机取色，使用固定柔和饱和度与明度，已有课程编辑不重新选色。无第三方UI依赖。

## 6. 提示、确认与状态生命周期

所有错误和警告进入发生问题的窗口底部消息栏，不调用 MessageBox 或独立警告弹窗。每窗口拥有自己的FIFO队列；每条完整展示约5秒，从切换可见开始计时，待显示消息不提前过期；队列清空后折叠。完整文本换行，无跑马灯依赖。多个错误可汇总为一条有换行的消息，提示栏可在受限高度内滚动。

无效字段保留字段错误样式，保存保持禁用或被校验阻止；临时消息消失不会使非法数据变为可保存。窗口关闭释放计时器和事件订阅。当前消息中途不被新错误覆盖；连续重复的相同待显示消息合并，避免无限重复排队。

删除课程、恢复默认、丢弃未保存修改用当前窗口内确认区域；课时预览刷新直接覆盖草稿表格，是不确认的明确例外。关闭有未保存修改的窗口先取消关闭，显示放弃修改/继续编辑；确认后才关闭。确认不受5秒消息时限限制，不另开警告窗。

子窗口异常在子窗口显示；父窗口文件保存失败在父窗口显示且保持草稿可重试。禁止保存失败后先显示成功或关闭窗口。

## 7. 职责与建议目录

建议工程为 src/ClassSchedule（WPF）与 tests/ClassSchedule.Tests（规则和存储测试）。本机已确认安装 .NET SDK 10.0.400，建议目标 net10.0-windows；不在设计阶段安装依赖。

| 部分 | 职责 |
|---|---|
| Models | StudentDocument、StudentSettings、TimeGenerationSettings、ClassPeriod、Course、ScheduleEntry；普通数据，无控件依赖 |
| Domain/WeekCalendar | 日期周次映射、保留日期的归属转换 |
| Domain/TimetableValidator | 数据合法性、时段重叠；同一课程内部也检查 |
| Domain/ClassTimeGenerator | 按三段起点生成默认时间 |
| Domain/WeekSelectionParser | 周次输入转为规范集合 |
| Storage/StudentFileStore | 具体JSON读写、文件扫描、姓名路径校验、外部变更检查 |
| ViewModels | 各窗口状态和命令，草稿协调；NotificationQueue维护本窗口消息状态 |
| Views | XAML及合理code-behind：焦点、滚轮、拖动、窗口owner、模态打开、计时和展示适配 |
| App | 启动时手动组装依赖，控制单实例生命周期 |

ViewModel不持有具体Window、不查找控件、不直接解析JSON。View接收编辑结果后调用ViewModel完成协调，不为少量窗口引入通用导航服务。业务类不引用WPF或ViewModel。基础设施仅需小型属性通知基类及命令类。

冲突判断：weeks有交集、星期一致且占用节次有交集即冲突；同课程重复同样拒绝。课时表本身已禁止时间重叠，无须另建时间冲突体系。

## 8. 持久化与异常恢复

所有保存使用独立候选文档：完整校验→序列化到同目录唯一临时文件→刷新关闭→原子替换/首次不覆盖创建→成功后发布内存状态。失败保留原文件及编辑草稿，只清理由本次操作创建的临时文件。不得先覆盖再验证。

新建用不覆盖语义；已有文件保存前比较加载时与磁盘当前内容指纹，发现变更或删除则拒绝覆盖，在原窗口提示先刷新。程序通过命名互斥量限制同时运行的本程序实例，避免内部并发写；不支持与外部编辑器同时写同一文件，指纹检查不能承诺跨进程强事务锁定。

更新保留一份同学生.bak备份；仅扫描*.json。备份读取恢复作为故障处理，不在本版增加备份管理页面。不合法JSON不自动覆盖、修复或替换为备份。EXE目录无写权限时提示具体路径和原因，不静默切换其他数据目录。

## 9. 视觉、部署与验证

当前尺寸：主窗口600×600 DIP、屏幕居中；总体设置600×600、课程管理520×540、时段320×390，独立子窗口均与直接owner居中。学生管理320×340 DIP独立开窗，课程编辑使用课程管理窗口切页。基础样式见[紧凑界面计划](compact-ui-plan.md)，后续交互以当前需求为准。课时预览只在总体设置出现，五列等宽、行及表头28 DIP，文字双向居中。

浅色Windows 11风格、12–16 DIP圆角、低饱和色、可见焦点与中文字体回退。窗口可调整，弹窗按owner居中、限制在当前显示器工作区；小屏幕表单可滚动，底部按钮与提示可达。避免手绘整套窗口框架，先使用可靠系统窗口行为。

部署建议为Windows x64依赖框架单文件发布（不包含.NET运行时）；data仍位于EXE旁。调试运行使用构建输出目录的data，不覆盖源码资源。发布脚本保留现有data，不打包或推送真实学生数据。

验证分层：

1. 日期：两种周日归属、周日边界、跨年、学期外日期；来回切换前后每课程实际日期集合严格相同，涵盖首周周日和末周周日、8/10节、空课程。
2. 课时与周次：分段生成、手改保留、时间倒置/重叠、单/双周、混合区间、非法输入、one/two合法节次及地点空字符串。
3. 冲突与保存：同门/不同门重叠、部分周交集、取消草稿、保存失败不发布状态、学生隔离、模式锁定、10→8及缩短学期拒绝非法结果。

## 10. 实施顺序与默认设计选择

实施顺序见[实施计划](implementation-plan.md)：数据与日期规则→文件存储→学生与设置流程→课程编辑与主表→通知及交互核验→发布验证。

当前默认选择：总周数1–104、时长1–180；双击新建时段默认仅当前浏览周（独立添加时默认整个学期）；新学生单节、课程数0时可改模式；学期外显示最近合法周；归属转换与手动学期范围调整分次保存；恢复默认仅恢复课时；删除等原窗口内确认、刷新不确认；单实例；依赖框架x64发布。核心范围、字段命名、地点可空、日期保持、冲突禁止保存及约5秒底部消息规则均来自确认要求。

公共视觉规范见[统一UI计划](unified-ui-plan.md)：App.xaml提供ParameterLabel、CommentLabel、ComboBoxItem、全局ScrollBar及共享SelectionOverlay/SelectionGlow；Ui.Label/Note集中引用标签类别。DataGridRow将选中层放在单元格内容后方；GroupedCourseTable使用不拦截鼠标的整组叠加层，避免改变合并名称背景或命中逻辑。横向滚动条模板按方向切换轨道与命令，不强制竖向。

内容高度和课程名色块以[内容适配修订](content-fit-plan.md)为准；主窗口仅保留滚轮切周与回到本周，不再维护左右按钮的启用状态。

运行时缺失提示使用.NET原生apphost，在WPF启动前显示安装所需Windows Desktop Runtime的提示和下载入口，不额外引入启动器。该启动前提示不适用已启动窗口的底部消息栏规则。

审查整理：ObservableObject.cs仅负责INotifyPropertyChanged基础能力；WorkspaceViewModel.cs独立负责学生选择、刷新和保存协调，不改变其公开接口。发布检查可运行tests/RuntimeChecks.ps1，验证不捆绑运行时及原生缺失提示。

## 当前窗口实施结构

StudentWorkspaceViewModel协调Courses/Course/Settings及Leave/Dates/Delete/ResetTimes确认状态；独立于控件。CourseViewModel、SettingsViewModel各自比较原始可编辑字段判断IsDirty，Build不修改课程草稿。StudentWorkspaceWindow负责共享底部提示、确认和焦点；CourseListView、CourseEditorView、SettingsView采用XAML结构，复用现有控件与业务规则。主题集中到Resources/Theme.xaml，隔离UI检查加载同一程序集资源，不触发生产Startup。旧CourseManagerWindow/CourseWindow/SettingsWindow/NewStudentWindow不再存在，ScheduleWindow独立保留。

GeneralSettingsWindow和CourseManagementWindow是共享StudentWorkspaceWindow壳的两个独立入口，不增加导航框架，也不重复确认/保存逻辑。设置窗口只呈现SettingsView；课程窗口在CourseListView和CourseEditorView之间切页。SettingsView按内容宽度530 DIP断点并排/堆叠，基本标签92 DIP、参数标签70 DIP、单选项78 DIP、时间框43 DIP。CourseNameCell以8层半DIP圆角边缘过渡保持中心原色，课程选择叠加层仍不拦截命中；管理表前三列固定120/110/70 DIP。

SingleInstance仅负责启动互斥量及窗口激活消息：已有实例时不创建主窗口，使用Win32窗口属性定位、转交前台权限并发送注册消息；原实例恢复主窗口并沿可见OwnedWindows链激活最深弹窗，不使用永久Topmost。

当前提醒与保存关闭行为以[课程提醒修订](course-reminders-plan.md)为准：ReminderSession纯计算每次发生与轮次，ReminderService只跟踪当前StudentSnapshot，ReminderWindow显示可合并的短时通知；声音复用MySchedule波形，不引用其日历/托盘。数字提醒字段在CourseViewModel/ScheduleViewModel以字符串持有，以免空文本转换失败后静默保存旧数字。设置提交成功关闭、取消草稿关闭；原生禁用最大化但不设置最大尺寸。

提醒时长通过CourseViewModel字符串草稿、ReminderSession的事件快照传入ReminderService，到期按该值关闭。schema2缺少该新增字段时默认1，不兼容其它旧字段/旧版本。空姓名列表通过鼠标/键盘输入拦截及DropDownOpened最后防线拒绝展开，提示仍使用原消息队列；显示文字内边距12 DIP=浮层4+选项8，实际到外框边缘为13 DIP。
