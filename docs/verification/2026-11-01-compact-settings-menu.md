# 设置菜单与分窗验证

按[确认方案](../design/compact-settings-menu-plan.md)实施：学生选择显示与下拉外框93 DIP，矢量齿轮及圆角菜单；总体设置600×600、课程管理520×600 DIP独立开窗，课程列表和编辑仍在课程窗口切页。设置两组默认并排、窄时堆叠，单选列对齐，单位后置，时间框43 DIP。管理表前三列120/110/70 DIP，课程名只在外缘约3–4 DIP向白色过渡。

## 验证证据

- 完整解决方案构建0警告、0错误；核心34组通过，WPF103项通过。新增检查覆盖姓名外框等宽、菜单次序、分窗尺寸和无跨页导航、并排与窄窗堆叠、单选列对齐、时间框与数字框实际宽度、固定列宽，以及名称色块中心像素保持原色。
- 布局实测发现基本信息标签84 DIP会使最长标签换行，改为92后高度17.8 DIP、保持单行。数字框继承的MinWidth90会覆盖预期64，已局部清除最小宽度，并加入实际测量断言。
- 独立只读复查未发现其他确认的正确性问题；没有增加领域抽象、第三方依赖或JSON字段。
- 使用隔离预览数据原生核对主界面、圆角菜单、独立总体设置、并排表单及520 DIP课程管理；课程色块中心实色、圆角外缘淡化正常。实测齿轮Space打开、Down选择和Return进入两个窗口；标题栏关闭设置后返回主窗口。
- 离线发布成功，Windows x64依赖框架单文件，不捆绑.NET；EXE为321172字节。RuntimeChecks通过：缺失.NET时原生宿主显示安装提示和下载链接。离线发布明确跳过在线NuGet漏洞检查。
- 发布前后dist/data的全部3个文件路径与SHA-256一致，包含JSON和备份；不把真实学生数据用于编辑测试。
- 发布EXE实际启动并显示新主界面，关闭时未编辑数据。26份Markdown的本地链接检查及git diff --check通过。

## 验证边界

未穷举各DPI、显示器和全部键盘/最小尺寸组合。自动布局、像素与状态检查不能代表所有原生视觉场景通过；原生预览中的父窗口目标Escape未形成可靠关闭证据，未将其计为通过。草稿关闭保护仍由现有WPF检查覆盖。本次不重试此前受认证阻止的GitHub上传。
