# ClassSchedule、学生管理与界面修订验证

## 实施与整理

- 项目、解决方案、源码目录、命名空间、程序集、互斥量、pack URI、测试及发布脚本统一ClassSchedule；中文名称和JSON契约不变。Git远程地址不变，当前工作区的外层目录仍是环境指定的ClassTimetable。
- 根目录Bee.ico用于EXE图标。其四个尺寸均为PNG压缩，WPF直接解码ICO失败，因而从原文件无损提取其256×256图像为Resources/Bee.png供窗口使用，保留原图标文件。
- 学生显示与下拉外框88 DIP，内边距5/1 DIP、姓名垂直居中；课程三页及总体设置标题居中，返回按钮靠左。
- 六个时间浮层自行消费滚轮，保持展开/选值/页面位置；SettingsView排除浮层视觉树，表格区域仍滚外层页面。
- 学生管理420×400 DIP独立开窗，新增/更新/删除；删除底部确认使用约定问句及是/否、默认否，否/Esc不修改，确认冻结表单；删除JSON和bak，删除最后学生后仍可新增。
- 新增、改名和删除通过WorkspaceViewModel及StudentFileStore协调；改名保留JSON/备份字节，检查重名/备份冲突/外部指纹，先获取主文件和备份句柄。主文件删除失败时恢复备份原名。
- 按项目code review skill与独立只读复查，修复打开管理窗口时当前文件被外部删除导致的未捕获异常；新增回归。移除旧NewStudentForm.xaml/.cs与NewStudentViewModel、主窗口内联表单及关闭状态，合并默认文档创建协调，移除无用using/默认配置；未引入通用仓储、事务框架或新依赖。

## 已验证

- 清理改名产生的旧bin/obj后重新构建；最终构建0警告、0错误，核心36组、WPF117项通过。
- 核心包括改名内容/备份字节保持、大小写改名、重名/备份占名、外部修改拒绝、备份占用和主文件只读失败保护，以及删除学生后其他学生不变。
- WPF覆盖新增/更新/删除、否与Esc、默认否焦点、确认冻结、未更新姓名切换保护、最后学生删除与再次创建、外部缺失文件打开错误；也覆盖6个下拉及末端滚轮不穿透、88 DIP外框、图标资源、标题居中和原有课程/设置回归。
- 原生隔离预览检查主窗口Bee图标/紧凑姓名、学生管理、删除底部问句及否默认焦点；实际点击否后表单恢复且学生保留。原生总体设置标题居中、分钟列表滚轮由00–15滚到05–20，保持展开与00选值、页面位置不变。最初通过父窗口句柄滚动会因工具激活父窗口关闭浮层，因此使用独立设置预览排除此干扰后验证，不将那次操作算作程序失败或成功证据。
- 离线Windows x64依赖框架单文件发布，未捆绑.NET；RuntimeChecks通过缺失运行时提示及下载链接检查。离线模式未执行在线NuGet漏洞审计。
- ClassSchedule.exe发布版实际启动成功，EXE为543369字节；旧名称EXE已移除。发布前后真实data全部4个文件的路径及SHA-256完全一致；28份Markdown本地链接及git diff --check通过。

## 边界

未穷举所有DPI、多显示器及全部键盘场景。跨JSON和bak的操作不保证断电原子性；已覆盖普通占用/只读/指纹失败，不为此增加事务基础设施。真实学生数据不用于增删改测试，发布前后比较文件路径及SHA-256。保留已有未提交重构，不将历史改动单独提交；本轮不重试此前认证失败的GitHub推送。
